# sleep

布娃娃休眠判定：用平均动能与位移方差估计静止，滞回阈值防抖动，休眠期间继续维护包围盒，
并把手动标注的休眠区间与判定结果逐帧比对，给出误判帧数上界与唤醒延迟。

`make test` 跑自检。

## 接口

```c
SlSleepConfig cfg = sleep_config_default();
SlState st;
sleep_init(&st, body_count, &cfg);          /* 阈值非法返回 0 */

for (each frame) {
    sleep_tick(bodies, body_count, &st, &tick);   /* 非法输入返回 0 */
    /* tick.sleeping[i]  本帧是否判睡
       tick.bbox[i]      该身体的扫掠包围盒（仅休眠时 valid）
       tick.bounds       整具布娃娃的并集包围盒
       tick.energy_mean / tick.variance_mean / tick.energy_total */
}

sleep_wake(&st, i);                        /* 外部事件强制唤醒 */
```

逐帧结果存进 `pred[]`，手工标注区间存进 `SlInterval[]`，再交给：

```c
SlEval ev;
sleep_evaluate(pred, nframes, truth, tcount, &eval_cfg, &ev);
/* ev.fa_frames    标注为睡、判成醒的帧数；
   ev.fa_bound     其允许上限；
   ev.miss_frames  标注为醒、判成睡的帧数；
   ev.miss_bound   其允许上限；
   ev.worst_latency / ev.wake_exceeded / ev.wake_bound；
   ev.ok           全部计数未超上界 */
```

## 度量定义

- 单身体动能 `E = 0.5 * m * |v|² = 0.5 * |v|² / inv_mass`。
- 单身体位移方差 `V = Σ_axis Var_axis(最近 4 帧位置)`，即 3×3 位置协方差矩阵的迹。
  轴向方差用 Welford 在线算法，避免世界坐标远离原点时 `E[x²]-E[x]²` 在 float 下
  相消。取**和**而非平均，是为了不让静止轴稀释运动轴：1D `±d` 两态抖动读作
  `V = d²`，同幅度的 3D 抖动读作 `V = 3d²`。
- 门限作用在**均值**（`energy_mean` / `variance_mean`）上而非总和，因此身体数量变化
  不需要重新调参；总和 `energy_total` 只作为诊断量输出。

> 方差窗口是最近 4 帧的**样本**方差（除以 N），4 个样本里只有一个离群点时读数是
> `3/16 · a²`，而非 `a²/4`。门限按上文的"幅度"给，窗口内离群点不足时读数偏小，
> 这是有意的：单帧尖峰不该单独否决入睡，它只把 hold 计数清零重来。

## 阈值取值与推导依据

下面单位取米，质量取 1（`inv_mass = 1`）。风格约定是 1 单位 = 1 米，60 Hz。

### 能量门限

`E_enter = 0.5 * m * v_quiet²`，`v_quiet` 是"算静止"的速度上限。取
`v_quiet = 4.5 cm/s`（一帧 16.7 ms 内位移 0.75 mm，肉眼不可辨识），
得 `E_enter = 0.5 * 0.045² = 1.0e-3`。

可用范围：`v_quiet ∈ [1 mm/s, 10 cm/s]`，即 `E_enter ∈ [5e-7, 5e-3]`。
- 下界依据 float 精度：世界坐标在 1e3 处 float 间距约 6.1e-5，仅浮点舍入就能在
  4 帧窗口里产生 `V ≈ 1e-9`；速度经积分器差分后等效约 1e-3 量级的伪运动。门限
  低于此会被数值噪声淹没。
- 上界依据可辨识性：持续 10 cm/s 的漂移任何观众都能看出来，再高就是把活物判睡。

### 方差门限

`var_enter = d²`，`d` 是"允许的位置抖动幅度"。取 `d = 1 cm`，得 `var_enter = 1.0e-4`。

可用范围：`d ∈ [0.1 mm, 5 cm]`，即 `var_enter ∈ [1e-8, 2.5e-3]`。
- 下界同上：`d = 0.1 mm` 在世界坐标 1e3 处已接近 float 分辨率，再小测不出。
- 上界：位置抖动 5 cm 已经可见。

方差门限与能量门限互补：能量看**平移**，方差看**原地高频抖动**（速度快但平均位置
不动、或速度恰好抵消的往复运动）。两者都低于 enter 才允许入睡。

### 滞回区间

`enter < exit`。进入休眠要**两个**量都低于 enter，醒来看**任一**量超过 exit。

记 `r = e_exit / e_enter = var_exit / var_enter`。由于量都是二次型，
门限之比 `r` 对应速度之比 `√r`。

**下界：噪声不能把睡着的身体吵醒。** 静止堆叠上的约束投影残差和穿插恢复会让单帧
速度有 RMS `σ`，按经验 `σ / v_quiet ∈ [0.05, 0.3]`。要让静止态噪声不至于每帧越过
exit，取 `v_exit ≥ v_quiet + 3σ`（高斯下 99.7% 分位），于是

```
r ≥ (1 + 3σ/v_quiet)² ∈ [1.32, 2.76]
```

`r = 1.5` 覆盖低噪端（`σ ≤ 0.075·v_quiet`），`r = 2` 覆盖到 `σ ≈ 0.21·v_quiet`，
噪声更大的软约束堆叠需要 `r = 3`。这就是下界取 1.5 的依据。

**上界：不能把开始运动的身体拖太久。** 若身体以加速度 `a` 从静止缓慢变快（推着
滑动、斜坡上让步），从 `v_quiet` 升到 `v_quiet·√r` 需要 `(√r − 1)·v_quiet / a` 秒。
取"有意思的最慢运动" `a = 0.5 m/s²`、唤醒延迟上限 6 帧 = 100 ms，得

```
(√r − 1)·0.045 / 0.5 ≤ 0.1  →  √r ≤ 2.11  →  r ≤ 4.46
```

所以 `r ≤ 4`。默认 `r = 2` 落在 `[1.5, 4]` 中间：既盖得住常见堆叠噪声，又不会让
缓慢起步的身体多等两帧以上。

> 这也是为什么"唤醒延迟超阈值要报告"比"直接判失败"更合适：滞回带本身就会刻意推迟
> 唤醒，`r` 取大值时延迟增加是预期行为，比对时应当能看到具体数值而不是只得到一个
> 红叉。

`hold_time` 默认 0.5 s（默认 60 Hz 下 30 个 tick）。它必须至少让方差窗口（4 帧）
填满，并长于接触求解尖峰的重现间隔，使偶发单帧尖峰只会把计数清零重来而不会让整体
判睡；可用范围 `[0.1 s, 2 s]`。hold 用**整数 tick 计数**而非浮点秒累加，因为浮点
累加会漂移：例如固定步长取 16 ms 时，`0.016f * 32 = 0.51199997`，比 `0.512` 小，
于是凭空多等一帧。

### 负阈值

能量与方差都是平方和，恒非负；负阈值不只是无意义——它会让"低于 enter"对所有身体
恒成立，整具布娃娃会被静默判睡。因此 `sleep_config_valid` 要求四个阈值严格为正、
有限，且 `exit > enter`，`sleep_init` 和每一帧 `sleep_tick` 都会复查；违反即返回 0。

## 休眠期包围盒

- 每个身体保存自己的扫掠盒：入睡时以当前 AABB 初始化，之后每 tick 与当前 AABB 求并，
  所以即便"睡着"的身体被积分器或外力推动，接触代理仍然覆盖它。
- `tick.bounds` 是所有身体的并集盒：睡着的用扫掠盒、醒着的用当前盒。
- 身体一醒，它的扫掠盒立即失效（`valid = 0`），下次入睡重新生成，不会无限膨胀。

## 与手工标注比对

- 标注区间半开 `[start, end)`，越界自动裁剪；重叠区间取并集；`start >= end` 的
  畸形区间不贡献任何帧。
- 误判帧数上界取 `ceil(frac * 对应标注帧数 - 1e-6)`：
  - `fa_bound = ceil(fa_frac * 标注头晕帧数)`；
  - `miss_bound = ceil(miss_frac * 标注醒帧数)`；
  - 比例取 0 表示"一帧都不许超"（`-1e-6` 防止 `ceil(1.0f)` 之类的浮点毛刺多给一帧）。
- 唤醒延迟从**标注边界**算：标注从睡转为醒的第一帧 `f`，若届时判定仍为睡，就数到
  判定首次为醒为止。窗口内一直没醒则记 `nframes - f`，故意取大值让上界必然触发。
- `wake_exceeded` 是超过 `max_latency` 的唤醒事件数，`wake_bound =
  ceil(lat_frac * wake_runs)`；`wake_exceeded > wake_bound` 才算失败，但
  `wake_exceeded` 与 `worst_latency` 始终会报告，所以"超阈值"是可见的即便整体
  `ok`。
- 默认 `max_latency = 6` 帧（60 Hz 下 100 ms）；`lat_frac = 0.1` 允许 10% 的唤醒
  事件超标。注意滞回带本身会刻意推迟唤醒（见上），这是设计取舍，不是 bug。

## 自检覆盖

文档里的每条断言都有对应用例：阈值拒负/拒 NaN/拒 Inf/拒非严格滞回；静止在
`hold_ticks` 帧入睡；移动与原地抖动都不入睡；滞回带内既不醒也不重睡；方差门限独立
生效；休眠包围盒随身体扩张且唤醒后失效；外部唤醒立即生效且需重新计满 hold；方差窗口
单点尖峰的精确数值；以及标注比对的误判计数、上界收紧后 `ok` 翻转、永不入睡/永不醒
两端的延迟与误判。`make test` 输出 `all_ok=1` 即通过。
