# solver

IK（`ik/` 的解析双骨解）与约束链（`constraint/` 的 Verlet 距离/碰撞约束）的
集成求解器：同一套原语，只在**帧内求解顺序**上分两种策略，用来复现并修复
「IK 与约束顺序不同 → 手穿进身体」。

| 策略 | 帧内顺序 | 结果 |
|---|---|---|
| `fixed`（修复） | 每帧固定：积分 → IK → 距离/碰撞约束 | 碰撞投影是最后一步，手停在躯干外，穿模像素恒为 0 |
| `legacy`（现状） | 顺序按帧翻转，偶数帧约束先行 | 约束先行的帧被 IK 覆盖碰撞结果，手穿进躯干 |

关闭固定顺序（`legacy`）后姿态回到改动前的现状：legacy 的 I 帧与 fixed 逐
字段一致，C 帧复现原始穿模姿态。

## 命令

```sh
make test     # 自检：确定性、fixed 零穿模、legacy 复现穿模、K4/K16 均零穿模
make accept   # 重新生成 ../artifacts/solver 下的姿态/穿模/耗时 CSV 与 PPM 帧
make verify   # 独立三向像素核对 + PNG/GIF + 生成 ../artifacts/solver/REPORT.md
make clean
```

`./solver --accept OUTDIR` 默认写 legacy，`--fixed` 写 fix，`--k16` 选迭代档。

场景（2D）：肩 `(-0.5, 1.5)` 固定，上臂/前臂各长 1.0，躯干为圆心
`(0.6, 1.5)`、半径 `0.9` 的圆；IK 目标沿 `x = 0.4 + 0.6cosφ, y = 1.5 + 0.6sinφ`
走一圈（整条轨迹都在躯干内），所以 IK 与碰撞约束必然冲突——这正是顺序敏感的
来源。

零穿模不是"碰巧调好参数"：碰撞约束对肘/手粒子及两条骨段各留一个按自身像素
尺寸推导的安全余量，且约束迭代以碰撞投影收尾，之后不再有距离投影把手拉回圆
内。`make verify` 从姿态 CSV 用独立的 Python 光栅器重算一遍，并直接数 PPM 中
的红色像素，三方一致才通过。

验收数据、逐帧明细与复现步骤见 `../artifacts/solver/REPORT.md`。
